## 三c、关于 `_bc` 的"不透明度重标定"：**不是官方的**

### 3c.1 官方包只有 prune + merge 两步

`/mnt/home1/wyq/nanogs-work/gpu5x/official/nanogs/` 全部内容：
`__init__.py`、`simplification.py`、`utils/{cost,merge,params,ply_utils,splat_utils}.py`。

`simplification.py` 的完整函数表：`knn_indices`、`edge_costs`、`knn_undirected_edges`、
`greedy_pairs_from_edges`、**`prune_by_opacity(threshold=0.1)`**、`simplify`、`main`。

对 `rescale|budget|recalib|scale_opacity` 的全文检索结果：**空**。
→ **官方仓库与论文都没有"不透明度重标定"，唯一涉及不透明度的是：①合并公式 `a_i+a_j−a_i a_j`（`merge.py:78`）；②合并前按 `op<0.1` 剪枝。**

### 3c.2 `_bc` 来自本地脚本 `ghap-work/rescale_opacity.py`

该脚本自带的 docstring 就写明它是 **GHAP 实验的对照工具**：

```
--factor F      alpha <- clip(alpha * F)
--target-mean M alpha <- clip(alpha + d), d solved so mean(alpha) == M
The additive form can hit the target mean even when many alphas saturate at 1,
so it is the fair 'same opacity budget, no spatial fitting' control.
```

实现方式（`rescale_opacity.py`）：
- **乘性**：`α' = clip(α · F, 0, 1)`
- **加性**：二分 80 次求 `d`，使 `mean(clip(α + d, 0, 1)) = M`，再整体平移
- 只改 opacity 字段，其余（位置/尺度/旋转/SH）原样写回

`ghap_reduce.py` 里也有同源的 `target_mean` / `calibrate` 选项（第 140、237 行）。

→ 所以 `truck10_nanogs_bc` 的 21.26 = **官方 NanoGS 输出（19.31）+ 本地全局加性不透明度平移**，op_mean 从 **0.8515 → 0.6854**。

### 3c.3 为什么一个全局平移能涨 1.95 dB

合并公式 `a_m = a_i + a_j − a_i a_j` 是**透射率并集的峰值**：它让合并后的单颗高斯在峰值处亮度正确，但合并椭球**面积变大**（相邻高斯的协方差和远大于二者），于是**整体覆盖被系统性高估** → 不透明度偏大 → 画面偏亮。一个全局下移就能把这部分偏差压回去，因此拿到 +1.95 dB。

**这恰好说明**：真问题是"合并后不透明度需要按空间重新拟合"，而不是全局常数。我们的 O2cal 做的正是**逐 pair 最小二乘拟合**（不是全局平移），所以在同一基础上再高 **+0.10 dB**（21.4175 vs 21.2606），且相对官方基线高 **+2.10 dB**。

| "NanoGS 自身输出（含其 opacity 优化）" | **官方 NanoGS 输出 + 本地 `rescale_opacity.py` 全局平移**；官方本身只有 prune+merge |
| "NanoGS 的 opacity 优化" | 官方无此步骤；`_bc` 是本地对照 |
| 与 M2 同阶段可比（+0.16 dB） | 仍成立，因为 `_bc` 确实也做了"某种"不透明度补偿，且**我们的更好** |

**结论：那 2.40 dB 的差距里，只有约 0.16 dB 属于"更好的不透明度拟合"，其余约 2.24 dB 来自"在渲染损失下对 DC 颜色 + 不透明度的联合重拟合"。** 我们的方法**从不触碰 SH、也没有渲染损失信号**，原理上拿不到这部分——这不是实现差距，而是方法边界的差距。

这也解释了为什么"逐 pair 闭式解"只能赢 +0.16：它只解不透明度这一维，而微调解的是二维耦合问题。

## 三e、DC（前三阶 SH）闭式拟合试验（仅 truck）

### 3e.1 方法

与不透明度同源的最小二乘，目标函数

$$\min_{c}\int G_m\,(c-c_{\text{ref}})^2,\qquad c_{\text{ref}}=\frac{a_iG_ic_i+a_jG_jc_j}{a_iG_i+a_jG_j}$$

闭式解：

$$c=\frac{a_iJ_ic_i+a_jJ_jc_j}{a_iJ_i+a_jJ_j},\qquad J_k=\int G_mG_k\propto\sqrt{\det(\Sigma_m+\Sigma_k)}\,e^{-\frac12\Delta\mathbf u_k^\top(\Sigma_m+\Sigma_k)^{-1}\Delta\mathbf u_k}$$

逐 (pair, view) 求 `c_v`，再按与不透明度相同的视角权重聚合后写回 `f_dc`。实现见 `o2_analytic.dc_color_fit`，开关 `--o2-fit-dc`。

### 3e.2 结果（truck，ρ=0.10，M2 基座）

| 配置 | PSNR | SSIM | LPIPS | wall |
|---|---:|---:|---:|---:|
| `M2`（仅不透明度闭式） | 21.4175 | 0.7233 | **0.3343** | 8–12 s |
| **`M2c`（+ DC 闭式拟合）** | **21.4687** | **0.7245** | 0.3357 | 7 s |
| Δ | **+0.0512** | +0.0012 | **−0.0014** | ≈0 |

### 3e.3 判读

1. **+0.051 dB 高于 0.012 dB 噪声地板，是真实增益**，但只占 2.10 dB 总增益的 **2.4%**。
2. 与移植消融对照：**完整 SH（48 维）在渲染损失下值 +0.71 dB**，而**仅 DC(3 维) 的闭式解只值 +0.051 dB** → 那份 SH 价值主要不在 DC，而在**高阶系数**与**渲染损失信号**。
3. **感知指标轻微反向**（LPIPS +0.0014），与"精修亮度/颜色提升 PSNR 但略伤感知"的常见规律一致。
4. 耗时几乎不变（同一次运行内 7–12 s 波动，无额外开销）。

**结论**：`--o2-fit-dc` 保留为**可选开关**（默认关闭），不进入主线默认配置——增益太小且 LPIPS 略降。

### 3e.4 调试记录（三处 bug，均属实现级）

| 现象 | 根因 | 修正 |
|---|---|---|
| OOM（请求 63 GiB） | `ai` 是 `(K,1)`、`wi` 是 `(K,)` → 广播成 `(K,K)` | 统一展平成 `(K,)`，混色时再 `[:,None]` |

**增益：+1.52 dB（1000 iter）/ +1.80 dB（2000 iter）**，且 SSIM +0.049/+0.057、LPIPS −0.032/−0.038 全面改善。

### 3f.3 三条结论

1. **大部分"微调差距"确实廉价可回收**：NanoGS 用 15k 迭代（139 s）做"SH + 不透明度"联合微调后是 **23.8221**；我们把**几何与不透明度全部冻结、只训练 SH**，用 2000 迭代（≈23 s）就到 **23.2650**，**只差 0.56 dB，快约 6 倍**。
2. **收益来自测试集，不是过拟合**：训练用训练相机、评测用留出测试相机，+1.80 dB 是真实泛化增益。
3. **对比我们自己的闭式 DC 拟合**：闭式 DC（+0.051）远小于渲染损失训练的 SH（+1.52/+1.80）。差别有两处——**高阶 SH 系数**（闭式只动 DC 3 维）与**渲染损失信号**（闭式无）。这与 §3d 移植消融的结论（完整 SH 值 +0.71）方向一致，且在这里拿到更多。
