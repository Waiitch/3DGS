## 0. 一页结论

1. **方案的前提被证实，且四种判据给出的结论一致**：固定 8 视角在 pass-1 上有
   **18.6% / 14.8% / 17.2%**（truck/room/garden）的 pair 没有任何有效 patch 支撑，
   平均支撑只有 **3.08 / 2.36 / 2.88**；换成全部 fit 相机后零支撑降到
   **0.04% / 0.06% / 0.33%**，平均支撑 **64.0 / 59.5 / 42.6**。
   我们实测的判据与历史报告（18.8 / 15.0 / 17.2，3.07 / 2.36 / 2.88）在 0.2 个百分点内一致。
2. **"信息量"准则（方案 P3，max d）不成立**：O2cal 的 patch 是自适应尺度（±2σ、9×9 网格），
   因此单视角的 `d = Σ G_m²` 几乎与高斯大小无关（truck 上 q10 = 2.10，中位数 ~2.2），
   按 `d` 排序退化成"挑投影面积最大（离相机最近）的视角"，三场景 E_alpha 全部差于按覆盖挑。
3. **轨迹分层 + 支撑修复（P4）是离线指标下三场景最稳的 pair-conditioned 规则**：
   B=8 时 E_alpha = **0.0343 / 0.0375 / 0.0648**，明显低于 fast8（0.3123 / 0.1614 / 0.2515）
   与 cover（0.0499 / 0.0553 / 0.0734）。
   ⚠️ **但这个排序没有迁移到端到端**：实测 cover ≥ repair/pref ≥ fast 于 truck/room，
   而 garden 上 fast 最好、任何修法都掉点（见 `REPORT-pics-e2e.md` §4）。
4. **预算曲线在 B≈6–8 之间已经饱和**：truck 0.0422(B=6) → 0.0386(B=8) → 0.0258(B=12)；
   room 0.0409 → 0.0379 → 0.0357；garden 在 B=6 出现非单调（0.0867）→ 0.0650(B=8) → 0.0444(B=16)。
   即"每个 pair 用 5–6 个**有效**视角"就能拿到大部分收益，view 数不是主要瓶颈。
5. **E_alpha 不能单独预测端到端**（这正是方案 §24 要求交叉验证的地方）：
   garden 上 `E_alpha` 排名是 track(0.027) < pref(0.051) < repair(0.065) < cover(0.073) ≪ fast(0.252)，
   而端到端排名**完全相反**：fast 21.348 > guard 21.223 > cover 21.200 > repair 21.172 > track 21.129；
   bicycle 上同理（只修 21% 的零支撑 pair：−0.162 dB）。
   即"更接近全相机 O2cal 解"在 garden/bicycle 上是**负收益**。因此本报告只把 `E_alpha` 当作**筛选器**
   （识别"根本没拟合上"的方案），最终判定一律以端到端为准（见 `REPORT-pics-e2e.md`）。

| 代号 | 定义 | 与方案对应 |

   渲染时真正看见该 pair 的方向系统性不同。这正是 §4.1/§4.4 里 garden 退化的几何原因。

## 3. Stage 2：相机选择对 O2cal 拟合的影响（离线）




因为 O2 的 `op` 不参与 cost / greedy（scorer 只看冻结的 S0 几何与 SH），
**同一份 dump 上的不同相机策略等价于"固定 pair 序列"的严格对比**（方案 §19.1）。

指标（方案 §17.3）：

- `E_alpha`：`mean |a(S) − a^all| / max(|a^all|, 0.05)`（分母加 0.05 下限，见 §5.2 说明）
- `E_abs`：`mean |a(S) − a^all|`（无下限，量纲与控制变量无关）
- `E_all`：全相机 proxy residual（用 `a(S)` 代入所有 `C_p^+`）
- `E_held`：未选视角上的 proxy residual
- `views`：每个 pair 实际参与拟合的有效视角数（决定 O2 耗时）
- `zero`：`C_p^+` 里一个都没选到的比例

1. **只修零支撑不够。** cover 把零支撑从 18.6% 压到 2.5%，但它对"本来能拟合的 pair"仍有

   但 strat 的 fallback 段（0.038/0.051）明显好于 cover（0.131/0.064）。
2. **strat 与 cover 的差别在 garden 上反转。** garden 的 `E_alpha_sup`：fast 0.0594、
   cover 0.0619、strat 0.0631 —— 三者几乎一样，说明 garden 的**支撑内**拟合质量对选视角不敏感；
   差别全在 fallback 段。这跟历史端到端"garden 上 cover 变差"的说法并不矛盾，
   但说明**E_alpha 不是 garden 的有效判据**（见 §5.1）。
3. `E_all` 对视角策略不敏感（0.11–0.18 之间变动），因为它主要由"合并高斯 vs 源覆盖"的
   固有失配主导；`E_alpha` 才是区分度所在。

| 残差驱动（全候选） | P7 | 0.0219 | 0.0316 | 0.0341 | 0.0306 |
| 残差驱动（top-16 候选） | P7′ | 0.0366 | 0.0486 | 0.0383 | 0.0352 |

自适应预算那一行的平均视角数是 14.8 / 14.9 / 13.3 / 13.3——**τ=1% 的停准则根本没起作用**，
它一路用到 B_max=16 才停；把 τ 提到 3–5% 才会真正省视角（见 §3.5 第 5 条）。

### 3.5 这些判据的结论

1. **track 冗余惩罚（方案 §11.6 / P6）是唯一在四个场景全部明显最优的判据**：
   0.020 / 0.035 / 0.027 / 0.026，约为 cover 的 1/2–1/3、guard 的 1/2。
   它的形式极简——`score = q − λ·max_{s∈S} M[c,s]`，M 是 COLMAP track overlap，
   解析一次只要 0.25–0.83 s，之后是 (V,V) 查表。
   这验证了方案 §6（MutualNeRF）的判断：**"位置不同但看到同样内容"的相机确实是冗余来源**。
2. **响应空间 D-opt/A-opt 确实比标量 FI 好，但仍不是正确的杠杆**：
   同一批候选中，标量 FI（按面积/d 排序）0.072/0.092/0.067，
   D-opt 0.053/0.057/0.045 —— 有 +0.02~0.035 的实打实改进，
   所以方案 §24 问的"response signature 有没有带来额外信息"答案是**有**；
   但它离 track 的 0.020/0.035/0.027 还差一倍，说明**信息论准则不是这里的主要矛盾**。
3. **T-opt（最大化 trace）三场景都最差**（0.061/0.072/0.058/0.052），
   与"标量能量"同类问题：它在奖励"响应大"的视角，而不是"补充已有响应方向"的视角。
   D-opt ≈ A-opt 说明当前签名下两个准则几乎等价（有效秩只有 8 维左右）。
4. **残差驱动（P7）在离线指标上第二好**（0.022/0.032/0.034/0.031），
   但把候选集压缩到 top-16（P7′，可部署版本）就退化到 0.037/0.049/0.038/0.035；
   而且它需要对候选视角做精确 patch（16 个候选 = 2× 的 fast8 计算量），
   部署代价高于 track。
5. **自适应预算的停准则要按"相对残差"重写**：τ=1% 时四个场景都用满 13–15 个视角，
   因为残差在 8 个视角之后仍以 >1% 的步长下降；若要真省视角，应把 τ 提到 3–5%，
   并把 B_max 收到 12。
6. **4 场景（含 bicycle）的排序完全一致**：track < 残差驱动 < cover/pref < … < fast。
   这是本轮唯一一个"跨场景稳定"的判据。

> ⚠️ **对这组离线数字的端到端解释已被复核修正**（见 `REPORT-pics-e2e.md` §7/§8）：
> 本轮端到端最初在 `--sh-clip 0.30` 下测，garden 的 track/guard 是负的（−0.219/−0.125）；
> **把 clip 调到仓库自己推荐的 0.05 后，四个场景全部转正**
> （truck +0.18、room +0.23、garden +0.06、bicycle +0.12）。
> 也就是说：**离线排序的方向是对的；之前的负号来自一个越界的 SH 超参，不是透明度拟合。**
> 另：`--sh-clip` 本身是本轮最大的杠杆（0.30 → 0.05 在 fast 臂上 +0.18~+0.83 dB）。

## 4. 机理：为什么"覆盖"有效而"信息量"无效

### 4.1 `d` 几乎与尺度无关

O2cal 的 patch 是**自适应尺度**的：采样范围取 `±σ_cut·r`、网格固定 9×9，
于是对近似各向同性的 merged 高斯有

```
d = Σ_x G_m(x)² ≈ (1/Δ²)·∫G² dA,   Δ = 2σ_cut r/(g−1),  ∫G² dA = π√detΣ₂ ∝ r²
⇒ d ≈ π (g−1)² / (4σ_cut²)   —— 与 r 无关的常数
```

实测 truck 上 `d` 的 10% 分位是 2.10、中位数约 2.2：确实被钉在常数附近。
所以方案 §11.3 的"标量 Fisher information = d/σ²"在这个参数化下**退化为常数**，
按它挑视角等于"按 footprint 面积（≈离相机远近）挑"，这正是 `info` 三场景都差于 `cover` 的原因
（truck 0.0715 vs 0.0499、room 0.0924 vs 0.0553、garden 0.0671 vs 0.0734）。

**对方案的修正建议：** 若要保留信息量路线，`d` 必须换成"**去掉 patch 自适应尺度后的量**"，
例如 `d/(g−1)² · (patch 覆盖的真实像素面积)`，或直接用投影覆盖的像素数；
否则标量 FI 与"挑最近的相机"等价。

### 4.2 为什么"分层"能赢

由于每个有效视角对 `a` 的权重近似相等（`d` 为常数），`a^all` 近似是 `C_p^+` 上
所有视角的单视角估计 `a_{p,c} = n/d` 的均值。要让 8 个视角的均值接近全集均值，
正解是**按轨迹分层抽取**（保证视角分布不偏），而不是挑最大的几个。

这解释了三件事：

1. garden 上快照的等间隔抽样（strat 的主干）本来就接近"分层抽样"，所以它的
   `E_alpha_sup` 与 cover 持平；
2. cover 在 garden 上退化，是因为贪心覆盖偏向"看同一片的相邻机位"，破坏了分层性
   （历史报告：选中索引 2,4,7,11,14,15,17,20）；
3. 把 strat 的槽位按"分层"补齐（`fill`）不会继续改善，因为**槽位已经不是瓶颈**——
   6 个视角之后边际信息很低（§3.2）。

## 5. 方法与边界

### 5.1 E_alpha 只是筛选器

cover 在 garden 上 E_alpha 更好（0.0734 vs fast 0.2515）但历史端到端是 −0.166 dB，
说明 **`a^all` 不是渲染质量的最优目标**：O2cal 只是"屏幕覆盖 ≈ 源覆盖之和"的代理，
全相机解本身也可能偏离渲染器需要的 α。方案 §24 已要求"由端到端判定"，
本报告的定位就是"筛掉明显错误的方向 + 给出机理"，不替代端到端。

### 5.2 指标的两处数值处理（必须写清）

1. **分母下限**：`a^all` 在 0.6–1.8% 的 pair 上接近 0（garden 最小 3.7e-13），
   原始相对误差会爆到 1e5 量级，故 `E_alpha` 的分母取 `max(|a^all|, 0.05)`，
   同时报告无下限的 `E_abs` 与中位数 `E_med` 作为交叉校验（三者的排序一致）。
2. **`C_p^+` 的定义**：用内核的 `patch` 掩码（不额外加 `d>τ_d`），
   并把 `E_alpha` 拆成"fast8 有支撑段 / fallback 段"报告，避免"修零支撑"的收益
   掩盖"支撑内质量"的差异（方案 §24 Stage 2 的判据）。

### 5.3 精度与对齐

- 新的 per-pair-camera 内核在**相同视角集**上与 `o2gpu.opacity_o2cal_gpu` 的
  最大差为 **5.9e-06**（float64 累加顺序差异），平均 1.4e-08（`debug_proj.py`）。
- 单实例 EWA 投影与 `o2gpu._project` 的最大差 **2.3e-10**；
  其间曾出现一次转置错误（`pc = w2vᵀ·ph`），由该对照捕获并修复。
- Stage 0 的三个历史数字（零支撑率、平均支撑、全池支撑）在 0.2 个百分点内复现。
